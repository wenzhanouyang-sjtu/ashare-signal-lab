# A股多信号量化研究框架

用真实的 A 股数据，回答一个具体的问题：

> **在计入 A 股真实交易摩擦之后，哪些信号能通过样本外验证与多重检验校正？**

这个项目的重点不是"找到一个赚钱的策略"，而是**把"这个结果是真的吗"变成可执行的检验**。
四类信号族、20 个参数组合、10 年日频数据、298 只沪深300成分股，全部结果都摊在
[`results/SUMMARY.md`](results/SUMMARY.md) 里，包括不好的那些。

---

## 核心结论（先看这个）

**1. 换手率决定了策略能不能活下来，而不是信号的预测力。**

高换手信号（约 52 倍/年）**并不都有正的毛夏普** —— 14 个组合里只有 4 个为正
（动量 250 日、低波动 20/60 日），其余 10 个毛口径就已经是负的。而即便是那 4 个，
成本按成交额线性累积，也把仅存的边际吃得干干净净：

| 信号 | 年换手 | 毛夏普 | 净夏普 | 十年累计成本 |
|---|---|---|---|---|
| 动量 250 日 | 51.7x | **+0.48** | +0.06 | 23.3% |
| 低波动 60 日 | 51.9x | **+0.46** | −0.11 | 24.2% |
| 反转 5 日 | 52.2x | −0.13 | −0.44 | 18.8% |
| 配对 min_corr=0.75, top_k=40 | **10.1x** | +0.68 | **+0.65** | **6.4%** |

（每行取该族内净夏普最好的那个参数组合，数字直接来自
[`results/summary_all.csv`](results/summary_all.csv)。「十年累计成本」= 期内
每日成本除以当日期初权益后求和，以初始净值 1.0 计 —— 因此是**成本占初始本金的
比例**，不是相对最终净值的比例。）

动量 250 日的净值曲线最说明问题：**毛净值 2021-02 见顶于 1.31，净净值却在
2024-02 跌到 0.94**（期末 1.02）——
毛口径赚钱、净口径亏钱。见 [`fig9_cost_drag.png`](results/figures/fig9_cost_drag.png)。

**2. 配对交易是唯一同时具备低换手与正毛夏普的信号族。**

6 个配对参数组合全部为正，净夏普 +0.46 ~ +0.65，年换手仅 10 倍。
以表中最好的那个组合（min_corr=0.75, top_k=40）为例，分年度 8/10 为正，
**但**收益集中在下半段（2015–2019 净夏普 +0.35，2020–2024 +1.07），
且 2018 年为 −0.87 —— 这不是一条平滑的曲线。

> ⚠️ **这一族的结果是在「理想化可做空」前提下取得的，读的时候必须带上这个前提。**
> 配对交易靠两条腿，其中一条是空头。而 A 股的做空受**券源可得性、借券费率、
> 券源召回、保证金比例与空头额度**共同约束 —— 本项目**一条都没有建模**，
> 引擎默认任何标的都能按需无限做空。这不是小数点级的简化：**唯一表现好的信号族
> 恰好是最依赖做空的那一族**。真实约束下的净夏普只会更低，不会更高。
> 详见已知局限第 5 条。

**3. 这个结果没有通过多重检验校正。**

在 N = 20 次试验下，纯噪声能达到的最大夏普期望值（年化）是 **+0.88**，
而最优信号的净夏普是 **+0.65** —— **低于噪声上限**。
置换检验 p 值、FDR 校正、Deflated Sharpe 的具体数字见
[`results/SUMMARY.md`](results/SUMMARY.md)。

这是本项目最重要的一条结论：**一个看上去不错的回测结果（+0.65 夏普、10 年、
计入全部固定费用），在正确计入"我试了 20 次"之后，不足以声称有真实技能。**
招聘方看重的正是"知道自己结果的置信边界在哪里"。

（这里说的是"全部固定费用"而非"全部成本"：冲击成本因量纲问题实际未生效，
且融券约束完全未建模 —— 两者都只会让真实结果**更差**，
所以这条否定性结论**不会因为补齐它们而翻转**。）

**4. 等权买入持有跑赢了全部 20 个策略。** 见 [`fig1_equity_curves.png`](results/figures/fig1_equity_curves.png)。

## 这个项目在方法上做了什么

多数个人回测的问题不在于代码写错，而在于**默认了一堆对自己有利的假设**。
下面每一条都对应代码里的一个具体设计，以及一个具体的检验。

### 1. 点位数据纪律（无未来函数，可验证）

- 信号在 `t` 日收盘后计算，只使用 `≤ t` 的数据
- 仓位在 `t + 1` 日**开盘**执行（`signal_lag = 1`，由引擎强制，调用方无法绕过）
- 不靠"看代码确认"，而是靠**截断不变性测试**：

  > 把价格矩阵截断到前 T 行后重算，第 T 行之前的信号值必须**逐位相等**。

  若某处用了未来数据（rolling 居中对齐、shift 方向写反、用全样本统计量做标准化），
  截断就会改变历史信号值，测试立刻失败。见
  [`tests/test_signals.py`](tests/test_signals.py)。

  另有一条"篡改未来数据"测试：只改 `t` 之后的收盘价，`t` 之前的信号必须一字不变 ——
  这条能抓出截断测试抓不到的隐蔽未来函数。

### 2. A 股真实摩擦

- **涨跌停**：主板 ±10%、创业板/科创板 ±20%、ST ±5%。封板时委托被**拒绝**，
  不是"假设能成交再打个折扣"。引擎单独统计被拒绝的委托笔数。
- **停牌**：停牌期间不可交易，价格前值结转。这条踩得最深，单独见下文「停牌的表示方式」。
  影响不是小数点级的：全样本 **1.70% 的股票-日处于停牌**，2015 年高达 **6.82%**
  （股灾千股停牌，**2015-07-08 单日 25.9% 的股票停牌**、33.8% 跌停、只有 74.1% 可买）。
  全样本有 **89 只股票出现过 ≥20 个交易日的连续停牌**，最长一段 **311 个交易日**。
- **T+1**：当日买入不可当日卖出。
- **费用**：佣金万 2.5（双边）、印花税 0.05%（仅卖出）、过户费十万分之一。
  印花税**统一按 2023-08-28 之后的 0.05% 计**，未按成交日切换历史税率：
  2015-01 ~ 2023-08 期间实际为 0.1%，因此**成本被低估**。这一项我实测了反事实
  （把税率改回 0.1% 重跑，`config.yaml` 里 `stamp_tax` 改一行即可复现）：
  配对族总成本 **6.4% → 8.9%（+39%）**，净夏普 **+0.646 → +0.629（−0.017）**，
  期末净值 2.017 → 1.970；全期一律按 0.1% 的最坏情况是成本 9.4%、净夏普 +0.626。
  不改变任何结论。修与不修，结论一致；如实标注比假装做全了更诚实。
- **冲击成本**：平方根律**已接入引擎，但在归一化回测中数值上失效**，
  实际贡献仅占总成本 0.17%。原因见下文「冲击成本为什么是零」。
  换言之：**目前真正起作用的只有固定费用**，不是"随流动性变化的冲击"。

成本敏感性作为一等输出：见 [`fig4_cost_sensitivity.png`](results/figures/fig4_cost_sensitivity.png)，
直接给出每个策略的**盈亏平衡成本**。

### 3. 双账本：把"信号有没有用"和"成本吃掉多少"分开

引擎同时维护两条账本 —— 实际账本扣成本，毛账本不扣，**两者执行完全相同的交易**。
于是恒等式 `毛净值 − 净净值 ≡ 累计成本` 精确成立（实测误差 ~1e-17）。

这不是为了好看。它让"这个策略是被成本吃掉的，还是本来就没边际"变成一个
可以**直接读出来**的事实，而不是靠推测。上面的核心结论 1 就是它的直接产物。

### 4. 三重检验，各针对一类具体的自欺

| 检验 | 针对的自欺 | 实现 |
|---|---|---|
| **置换检验** | "夏普是信号带来的，还是时间对齐的巧合" | 循环平移价格面板，重跑引擎 |
| **Walk-forward** | "在历史上挑最好的，在未来仍然最好吗" | 滚动窗口，比较样本内外排名 |
| **FDR / Bonferroni** | "20 次检验里总有几次走运" | Benjamini-Hochberg，已与 statsmodels 对拍 |
| **Deflated Sharpe** | "试了 N 次之后，最好那次本身就偏高" | Bailey & López de Prado (2014) |

置换检验有一个**容易做错的地方**值得说明：早期版本用 `w · r` 直接算策略收益，
看似便宜，但它和引擎**不是同一个策略** —— 引擎在调仓日按开盘价成交，而代理假设
旧权重吃满全天的收盘到收盘收益。实测两者在低换手信号上相关 0.99（可用），
在高换手信号上只有 **0.17**（不可用，等于在检验另一个策略，观测夏普甚至算出了
与引擎相反的符号）。

修正后的实现直接**平移价格面板并重跑引擎**。引擎单次 0.06~0.15 秒，
可接受的代价。原则是：**统计量与零分布必须出自同一条计算路径。**

还有一处**自由度虚报**值得说明：块长 20 日时，2431 个交易日只有
**121 个互不相同的位移**。早期实现从中**有放回**地抽 1000 次 ——
同一个零假设样本被反复计入，报出去的是"1000 次置换"，
有效样本却只有 121 个。现在改为**遍历全部不重复位移**
（`n_permutations` 降级为上限，超出时等间距无放回取子集）。
这既更诚实，也更快：**121 次引擎调用代替 1000 次**，且不再需要随机种子，
重跑给出逐位相同的 p 值。p 值的分辨率下限因此是 `1/(121+1) ≈ 0.008`，
已写进 `results/SUMMARY.md`。

检验本身的标定（见 `tests/test_validate.py`）：

- 纯随机信号 → p ≈ 0.20（不显著）✓
- 偷看未来 5 日收益的信号 → 毛夏普 +4.76，p 触到分辨率下限（正确识别）✓
- 真实反转信号 → p ≈ 0.48（不显著）✓

### 5. 参数网格的试验次数必须可数

`config.yaml` 里的 `*_grid` 参数被显式展开成笛卡尔积，
展开出的组合数**就是**多重检验的试验次数，会被写进每一个结果文件。
试验次数不可数，就无法判断一个漂亮的夏普是真实的还是搜出来的。

## 一个退化参数（值得单独讲）

最初 `pairs` 族的参数网格是 `min_corr × entry_z`（2 × 3 = 6 组）。
跑出来发现 `entry_z = 1.5 / 2.0 / 2.5` 三组结果**完全相同**。

原因不是 bug，而是一个配对交易的固有性质：当候选池有约 **2500 对**时，
"价差偏离 2.5 个标准差"根本不是稀有事件 —— 实测每周有 **60 ~ 190 个**配对的
`|z| > 2.5`，第 20 大的 `|z|` 从未低于 **2.87**。

因此在 `top_k = 20` 的约束下，`entry_z` **不 binding**，任何 ≤ 2.5 的阈值
都会选出同一批配对。**"N 个标准差"这个说法，在几千次扫描的语境下是失效的** ——
这正是多重检验问题在配对筛选层面的体现。

处理方式：把 `entry_z` 移出网格、固定为 2.0（并在 config 里注明原因），
换成真正 binding 的维度 `top_k ∈ {10, 20, 40}`。发现保留在上面的"一个退化参数"
和 `tests/test_signals.py::test_entry_z_does_not_bind_under_top_k` 里。

## 一个不会报错的 bug（也值得单独讲）

配对族第一次跑完时，6 个组合全部返回 `净夏普 NaN`、换手 0.0x、零交易。
但**没有任何异常抛出**，进程正常退出。

原因是权重矩阵初始化为 `NaN` 表示"该日不调仓"，随后用 `row[i] += w` 累加仓位。
`NaN + x == NaN` —— 所有写入被静默吞掉。

修好之后配对族从"完全无效"变成了表现最好的一族。这个 bug 说明一件事：
**回测系统里最危险的错误是不抛异常的错误。** 因此补了
`test_pairs_actually_takes_positions` 把该行为锁死。

## 停牌的表示方式（同一个坑的第二副面孔）

洗数据时写了一句很自然的判断：

```python
out["suspended"] = vol.isna() | (vol <= 0)      # 成交量为 0 即停牌
```

跑完统计，`停牌占比 0.000%`。不是低，是**一次都没命中**。

原因是数据源在停牌日**根本不返回该股票的行**，而不是返回一行成交量为 0 的记录。
（实测：`volume` 列 0 个 NaN、0 个 ≤ 0，最小值 500。）
于是"停牌"在数据里和"尚未上市"长得完全一样 —— 而这两件事对回测的含义截然相反：
前者是**有仓位但卖不掉**，后者是**根本不该有仓位**。

更麻烦的是，标错了也不报错：引擎恰好仍然是对的（缺失行 → 面板 NaN → 拒单），
所以净值曲线一切正常，只有 `suspended` 这一列和 SQL 里那栏统计在说谎。
**一个静默错误的标志，就是它不影响主流程、只污染你对主流程的解释。**

修法是把面板补全到「已上市 × 全部交易日」的完整网格：某只股票从首次出现之日起
视为已上市，此后凡是没有数据的交易日即为停牌。于是长表里两种状态终于可区分 ——
**未上市 = 没有这一行；停牌 = 有这一行但价格缺失、可交易性为 False**。

补出来的行价格是 NaN，而 **NaN 经引擎的 `ffill` 后与"整行缺失"完全等价**，
所以引擎行为不该有任何变化。这不是口头保证，而是测出来的（`tests/test_data.py`）：
补全前后 `open/high/low/close/volume/amount/turnover/can_buy/can_sell`
九个面板**逐位相同**，唯一变化的是 `suspended` 从全 False 变成 10,660 行 True。
正因为如此，这次修复**不需要重跑任何历史结果** —— 重跑 20 个组合后，
净值、夏普、换手、成本全部逐位一致（唯一差异是墙钟耗时）。

复牌日的处理也值得说一句：收益相对**最后成交价**计算，因此包含停牌期间的跳空。
若把停牌简单地按"收益记 0"处理而丢掉跳空，长停牌的尾部风险会被系统性低估 ——
上面那 311 个交易日的停牌，复牌是一次性重定价。

## 改了配置，但什么都没发生（第三副面孔）

`config.py` 里配置对象用点号访问，最初的实现是：

```python
def __getattr__(self, name):
    value = self[name]
    return Config(value) if isinstance(value, dict) else value   # ← 这里复制了一层
```

`Config` 是 `dict` 的子类，`Config(value)` 会**复制**这个字典。
所以 `cfg.backtest.costs` 每次返回的都是一个用完即弃的壳：

```python
cfg.backtest.costs.commission = 0.0     # 不报错、不生效、读回来还是旧值
```

对本项目来说这不是学术问题：**成本敏感性分析（`fig4_cost_sensitivity`）正是靠
"改配置 → 重跑引擎"来产出整条曲线的**。一旦赋值静默失效，那条曲线会退化成
一条水平线，而程序照常跑完、照常出图。

（现有的 `_scaled_cfg` 恰好用的是 `new["backtest"]["costs"]` 直接索引，绕开了
`__getattr__`，所以结果一直是对的 —— 但这属于运气好，不是设计对。）

修法是在构造时递归把嵌套字典包装成 `Config`，取值不再复制。
补了 `tests/test_config.py` 八条测试盯住它，其中一条直接断言
`cfg.backtest.costs is cfg.backtest.costs`。

## 冲击成本为什么是零（第四副面孔）

这个坑最隐蔽：它不是一句写错的判断，而是一个**量纲错误**。

引擎里净值归一化为 1.0，所以 `traded_value`（成交金额）的单位是"归一化组合单位"；
而 `daily_amount`（当日总成交额）的单位是**元**，量级 1e8~1e9。两者相除得到参与率：

```
参与率中位数   2.000e-11      最大 1.751e-08     （实测 9471 笔成交）
冲击费率 0.10 × sqrt(2.0e-11) = 4.47e-07   （即 0.0045 bp）
对比固定费率   买入 2.60e-04（2.6 bp）/ 卖出 7.60e-04（7.6 bp）
```

差了近三个数量级（2.6e-4 / 4.47e-7 ≈ 580 倍）。实测把 `impact_coef` 从 0.10 直接改成 0：

```
impact_coef=0.10   累计成本 0.064229   净夏普 +0.6459
impact_coef=0.00   累计成本 0.064119   净夏普 +0.6460
差额 1.1e-04  →  冲击项占总成本 0.17%
```

这不是"系数配小了"，而是**归一化回测在数学上无法表达冲击成本**：
冲击成本本质依赖 AUM 规模，而净值恒为 1.0 的回测里没有 AUM 这个量。
补上 AUM 它就会生效 —— 按 1000 万计，参与率升到约 2e-4 量级，
冲击费率约 **14 bp**，已经超过卖出腿的固定费用（7.6 bp）：
双边 28 bp 对固定的 10.2 bp，约 **2.7 倍**，冲击会取代固定费用成为主要成本项。

但那会把配对族的净夏普显著拉低，属于重做研究，本项目**未做**。
因此本文档与简历中**不再宣称"平方根冲击成本"是一等公民** ——
它是一段接好了、跑得动、却不产生数值影响的代码，
和上面三个坑同一个形状：**不抛异常，只是安静地什么都没做。**

## 已知局限（诚实清单）

1. **幸存者偏差（最重要的一条）。** 股票池用的是中证官网**当前**的沪深300成分股，
   拿不到历史成分。2015 年时属于沪深300、后来被调出或退市的股票不在样本里。
   这会让**多头**基准（等权买入持有）明显偏乐观。
   对配对这类多空策略影响较小（两条腿都在，且组合近似市场中性），
   但**不能声称无影响** —— 一个稳健的做法是用历史成分股重跑，本项目未做。

2. **股票池在时间上是不均衡的。** 日频有效股票数在 **156 ~ 298** 之间波动（中位数 256）：
   2015 年 1 月只有 195 只，2024 年 298 只 —— 当前成分股里约 **100 只在 2015 年尚未上市**
   （另有 2 只 2025 年才上市，两个数据源都取不到，已跳过）。
   这有两个后果：一是早期年份的**截面宽度明显更窄**，配对候选池（约 2500 对是 2024 年的量级）
   在 2015 年要小得多，因此**分年度结果之间不完全可比**；
   二是它正是上面幸存者偏差的另一种表现形式 —— 样本"越长越大"本身就不是真实投资域的形态。

3. **退市未被建模。** 停牌的识别方式（首次出现后即视为存续）在本数据集里成立，
   因为股票池全是当前成分股、无一只中途消失（已核验：0 只）。
   但若换成含退市股的全市场样本，这套逻辑会把退市误判成"永久停牌"，需要额外处理。

4. **参数网格很窄。** 20 个组合远少于真实研究中的搜索空间。
   如果把网格放宽 10 倍，噪声上限 SR₀ 会随之升高，结论只会更保守。

5. **没有考虑融券成本与可融券标的的限制（与核心结论 2 并列，不是次要限制）。**
   做空在实际 A 股中受**券源可得性、借券费率、券源召回、保证金比例、空头额度**
   共同约束，本项目**一条都没有建模**，引擎假设任何标的都能按需无限做空。
   这不是小数点级的简化：**唯一表现好的信号族恰好是最依赖做空的那一族**，
   所以"配对族净夏普 +0.46 ~ +0.65"必须读作**理想化可做空条件下的上界**。

6. **协整检验未实现。** `pairs` 族的筛选依据是**滚动相关系数**，
   不是协整关系 —— 没有 ADF、没有 Engle-Granger、没有半衰期约束。
   高相关不等于协整：两个各自随机游走的序列可以高度相关而价差永不回复。
   诚实的方法名是"高相关价差均值回复"。真正的协整筛选
   （训练窗内 ADF + 半衰期约束 + 只用训练窗选对）未实现。

7. **冲击成本实际未生效。** 平方根律虽已接入，但因归一化量纲问题参与率约 2e-11，
   仅占总成本 0.17% —— 详见上文「冲击成本为什么是零」。
   目前承担全部成本的是固定费率（佣金 + 印花税 + 过户费）。
   另需说明：样本内**最小日成交额低至约 4 万元**，即便补上 AUM，
   平方根律在这种流动性上的外推也不可靠。

8. **印花税未按成交日切换历史税率。** 统一按 2023-08-28 后的 0.05% 计，
   而 2015-01 ~ 2023-08 实际为 0.1%。实测反事实：配对族总成本 6.4% → 8.9%，
   净夏普 +0.646 → +0.629（−0.017），结论不变。

9. **样本期有限。** 10 年、含 2015 股灾与 2018 去杠杆两段极端行情，
   统计功效有限；单年夏普的标准误约 ±1.0，因此**单年数字噪声很大**，
   分年度结果只应看作定性证据。

10. **等权基准同样受幸存者偏差影响**，只用作量级参照，不是严格业绩基准。

## 快速开始

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python scripts/01_fetch_data.py        # 抓取并清洗数据（约 4 分钟，可断点续传）
python scripts/00_build_db.py          # 装载 SQLite 并跑预置查询（可选，见下）
python scripts/02_run_signals.py       # 20 个信号组合逐一回测
python scripts/03_validate.py          # 置换检验 + walk-forward + 多重检验校正（约 30 分钟）
python scripts/04_make_report.py       # 生成图表与 results/SUMMARY.md

pytest                                 # 42 个测试，重点是未来函数检测、成本恒等式与静默失效
```

复现性：**研究流程里没有随机数**。置换检验改为穷举全部不重复位移之后，
唯一需要种子的环节（有放回抽样）已经不存在，`config.yaml` 里的 `project.seed`
只是保留位。删掉 `results/` 重跑，结果逐位一致 —— 这是比"固定了种子"
更强的性质。

```
│   ├── data/                    # 股票池、抓取（新浪主源 + 腾讯备源 + 退避重试）、
│   │                            # 本地 parquet 缓存、清洗与可交易性标记

│   │   ├── costs.py             # 佣金 + 印花税 + 过户费 + 平方根冲击（后者未生效）
│   │   └── portfolio.py         # 截面组合构建、缓冲带、波动率目标
│   ├── validate/                # 置换检验、walk-forward、FDR、Deflated Sharpe
│   ├── report/                  # 绩效指标与图表
│   └── pipeline.py              # 02 与 03 共用的回测流程（避免两处逻辑漂移）
├── scripts/                     # 00 建库 → 01 抓取 → 02 回测 → 03 验证 → 04 出图
├── tests/                       # 42 个测试（信号/引擎/验证/数据/配置）
└── results/                     # 汇总表、逐日收益、图表、自动生成的 SUMMARY.md
```

### 设计说明：为什么还要一层 SQLite

可交易性是**随时间变化的属性**，把它物化成一张带索引的表之后，
任何信号研究都能直接 `JOIN` 上去，而不必每次重算涨跌停。更实际的是，
下面这类问题用 pandas 要绕好几行，用 SQL 是一句话：

> 2015-07-08 这天，沪深300 里有几只股票既没停牌、也没封涨停、且成交额足够大？

`scripts/00_build_db.py` 刻意把「行情」（市场事实）与「可交易性」
（本项目由事实推导出的判定，含规则假设）分成两张表 ——
混在一起会让"这个 `can_buy` 是怎么来的"变得不可追溯。
预置查询的输出在 [`results/db_findings.md`](results/db_findings.md)，
本文档里关于停牌与涨跌停的所有数字都出自那里。

### 设计说明：为什么要有 `pipeline.py`

`02_run_signals.py` 与 `03_validate.py` 需要**完全相同**的权重构建逻辑。
若两处各写一份，验证层就可能在校验一个与回测不同的策略 ——
这是最隐蔽也最致命的一类错误（验证看起来通过了，但对象不是被发现的那个）。
因此权重构建、回测执行、统计口径全部集中在 `pipeline.run_spec()`。
重构时验证过：20 个组合的夏普与原实现的最大差异为 **0.0**。

## 数据来源

- 行情：新浪财经 `stock_zh_a_daily`（主源，含换手率与流通股本）、
  腾讯财经 `stock_zh_a_hist_tx`（备源），经 `akshare` 获取

本项目环境实测东方财富接口不可达，故未采用；数据源可在 `config.yaml` 中切换。
